`npm run test:unit`: 7/7 files green. Gaps below are not covered by those tests. Ranked.

1. 2. Watchlist tab throws for synced items: `content.js:331` `stats(it.hist).now` on null; `sync.js:19` mergeWatchRow creates `hist: []` for rows from another device. Whole tab shows "Something went wrong". Fix: guard null stats, store `last_price` into item (`last`).
3. `background.js:50` onMessage async IIFE has no try/catch: storage quota or any throw means no reply, content `run()` (content.js:363) rejects and the skeleton stays forever. Fix: wrap, `reply({error})`.
4. Data-loss races: `sync.js:36-44` flush writes back a stale outbox snapshot (ops enqueued during the network call are dropped); a rejected watch batch (e.g. server limit trigger) blocks all later ops forever; `observed_at` is ignored by the RPC so offline obs land on the flush day. `background.js:5,22,36` get/put of whole `items` is racy (maybeAlert, afterSignIn overwrite concurrent edits). Also `sync.js:7` dedupe uses `String(at).slice(0,10)` (epoch seconds, not day). Fix: promise-chain mutex, remove only sent ops by id, drop poison ops, send observed_at.
5. Poisoning bypass: `0003:12,32-35` still grants INSERT on ext_price_observations, so direct REST inserts skip the 500/day cap and RPC validation. Fix: revoke insert + drop policy (RPC is SECURITY DEFINER). Also no length checks on name/title/url columns.
